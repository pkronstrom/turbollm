# Kev 4B local integration trial

Date: 2026-10-23. Apple Silicon Mac16,5, arm64, 128 GiB unified memory.

Kev 4B ran successfully through the official MLX backend. The retained September
Kev 0.8B checkpoint was also run on the same new fixture and runtime. Neither run
used hosted inference. Both child servers were stopped after measurement.

## Measured results

The fixture contains 36 labeled synthetic short cases: 12 choice questions
(support routing and agent actions), 12 yes/no completion questions, and 12
ordered severity questions. Three serial rounds measure 108 requests after six
warmup requests. Each round cycles all 36 states, exceeding the four-state prefix
cache. Score correctness uses the highest-probability level, not the rounded
expected score. Noul correctness uses a 0.5 threshold.

| Measurement | Kev 4B | Retained Kev 0.8B |
| --- | ---: | ---: |
| Unique short cases correct | 36/36 | 35/36 |
| Timed short requests correct | 108/108 | 105/108 |
| Warm short wall p50 / p95 | 104.0 / 127.6 ms | 25.6 / 28.6 ms |
| Cold process readiness, cached files | 4.63 s | 3.24 s |
| First inference after readiness | 188.8 ms | 115.7 ms |
| Peak child process RSS | 16.84 GB | 3.36 GB |
| Repeated-state questions correct | 20/20 | 11/20 |
| Repeated-state first request | 214.8 ms | 37.2 ms |
| Subsequent 19 wall p50 / p95 | 28.3 / 29.3 ms | 8.5 / 9.0 ms |
| Choice predictions stable after order reversal | 12/12 | 12/12 |

The repeated-state test uses a fixed 30-task ledger and asks whether each of
20 named tasks is complete. Kev 4B's cache counters changed from 0 hits / 114
misses to 19 hits / 115 misses, confirming one prefix miss followed by 19 hits.
The 0.8B routing error was `route-6`, an invoice tax question; its repeated-state
errors show why the faster model should be checked on the actual workload.

The two additional probes are unscored. For a deliberately equal billing and
shipping issue, 4B assigned shipping 0.783 and billing 0.217. Missing evidence of
completion yielded a yes probability of 0.0151. These are observations, not a
calibration guarantee. Reversing the 12 choice cases checks only two orders per
case. Empty questions, empty choice criteria, and empty score criteria all
returned HTTP 422.

This is a small, easy integration smoke fixture. It does not establish general
quality, uncertainty calibration, long-document accuracy, or equivalence to the
September 206-case corpus. The retained 0.8B checkpoint predates the current Kev
1.0 family. Its results here do not describe the latest 0.8B release.

All latency figures include localhost HTTP and JSON. p95 uses nearest rank.
Readiness starts a fresh server process with downloaded files already in the OS
file cache; it excludes installation/download and is not a cold-machine test.
Peak RSS is macOS `getrusage(RUSAGE_CHILDREN).ru_maxrss`, including load/LoRA merge
and inference, rather than an MLX allocator or steady-state memory measurement.
One model server ran at a time; no other model server was observed before the
trial. Ordinary background applications were not controlled.

## Serving and API

The provider uses the installed runtime directly:

```sh
env HF_HOME="$HOME/.models/.hf-cache" \
  HF_HUB_CACHE="$HOME/.models/.hf-cache/hub" \
  HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 KEV_BACKEND=mlx \
  "$HOME/.turbollm/runtimes/kev/.venv/bin/python" -m kev.serve \
  --run "$HOME/.models/jaredpalmer/kev-4b" --host 127.0.0.1 --port 8901
```

`GET /v1/models` supplies readiness and actual `run`, `base`, `backend`, `dtype`,
and cache statistics. There is no dedicated health route. The response contains
a `models` array with `name` aliases `kev-latest` and `jev-latest`; the alias alone
does not identify a checkpoint. `POST /v1/systemone` accepts:

```json
{
  "model": "kev-latest",
  "state": "All requested work is implemented and the required tests passed.",
  "questions": {
    "done": {"type": "noul", "instructions": "Is the work complete?"},
    "action": {
      "type": "choice",
      "instructions": "What should the agent do next?",
      "criteria": {"report": "Report completion", "continue": "Finish missing work"}
    },
    "quality": {
      "type": "score",
      "instructions": "How complete is the work?",
      "criteria": ["Not started", "Partial", "Complete and verified"]
    }
  }
}
```

Answers preserve their question IDs. Choice returns a selected label,
probabilities, and confidence. Noul returns a yes probability. Score returns an
expected zero-based level, level probabilities, legend, and confidence. Response
`usage.output_tokens` counts serialized answers; the model generates no text.

## Reproduction

The fixtures and full per-request outputs are durable:

- [Fixture](../../tools/benchmarks/kev-fixtures.json)
- [Driver](../../tools/benchmarks/kev-local.py)
- [4B raw results](../../tools/benchmarks/kev-4b-results.json)
- [Retained 0.8B raw results](../../tools/benchmarks/kev-0.8b-results.json)

```sh
python3 tools/benchmarks/kev-local.py \
  --runtime "$HOME/.turbollm/runtimes/kev" \
  --out /tmp/kev-4b-results.json
python3 tools/benchmarks/kev-local.py \
  --runtime "$HOME/.turbollm/runtimes/kev" \
  --run "$HOME/.models/jaredpalmer/kev-0.8b" \
  --out /tmp/kev-0.8b-results.json
```

The driver refuses an occupied port, starts only its own child on loopback,
disables Hub access, and stops that child in a finally block. A second real
inference through the implemented provider command verified the final local
4B adapter path and offline environment after `pull` reused the cached base.
